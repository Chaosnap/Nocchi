# 刘海冲印店：产品构想

> 暂定名，备选：Notch Darkroom、出片口
> 平台：macOS（之后可以扩展到 iPhone 的灵动岛）
> 状态：构想阶段

---

## 1. 一句话

把 MacBook 的刘海当成一台复古相机的出片口：截图或自拍之后，照片从刘海里"吐"出来，像真相纸一样慢慢显影，你可以甩它、在白边上写字、把它贴在桌面上，或者撕下一半分给朋友。

## 2. 为什么这个比喻成立

- **刘海里本来就装着摄像头。** 把它当成相机，不是硬套的比喻，而是这块硬件本来的身份。
- **摄像头一开，刘海里的绿灯就会亮。** 这颗灯可以直接当作相机的"营业中"指示灯。
- **好玩的不是拍照本身，而是仪式感。** 等出片、等显影、不能重拍、每张都不完美，这些都是真相机才有的感觉，软件照相通常把它们全省掉了。

## 3. 现有产品和我们的差异

| 产品 | 它做了什么 | 我们的差异 |
|---|---|---|
| 苹果自带 Photo Booth | 四连拍、白屏闪光 | 它只是一个普通窗口，没有"进到一台机器里"的感觉 |
| Archie | 把新截图自动收进刘海，做成收纳架（9.99 美元，2026 年 11 月上线） | 它是效率工具；我们做的是出片、显影、甩一甩的仪式 |
| NotchNook 这类刘海工具 | 把刘海做成灵动岛：音乐、文件架、计时器 | 功能型产品，没有实物比喻 |
| iPhone 上的复古相机 App（Huji、Dispo、Gudak 等） | 漏光滤镜、隔天才能看到照片的"冲洗"玩法 | 都在手机上；我们用的是 Mac 的刘海，拍的对象还包括屏幕截图 |

**定位：** 不是截图工具，也不是滤镜 App，而是一间开在刘海里的复古相机铺。

## 4. 核心体验：一张照片的一生

```
取景 → 按快门 → 从刘海出片 → 显影 → 写字和装饰 → 贴在桌面 → 收进相册 → 分享
```

每一步都要做出实物感：

1. **取景**：有两种素材来源。
   - 屏幕快门：截下屏幕上的内容。
   - 自拍：用前置摄像头拍自己。
2. **按快门**：机械快门声，屏幕边缘闪一下。
3. **出片**：相纸伴着马达声从刘海缓缓滑出来。在有压感的触控板上，每吐出一截就"咔"地震一下。
4. **显影**：刚出来时是灰的，十几秒内慢慢显出颜色。
   - 按住照片甩几下，显影会变快。
   - 彩蛋：现实中其实不建议甩拍立得，所以甩得太猛，照片上会出现色块。
5. **写字和装饰**：在白边上用触控板手写一句话，笔画粗细跟着按压力度变化。
6. **贴在桌面**：照片是一个能拖动的实物，可以像冰箱贴一样吸在屏幕边缘。
7. **收进相册**：所有照片贴在一面软木板上，按月份排开。
8. **分享**：导出带白边的成片；大头贴可以"撕成两半"，其中一半生成分享图。

## 5. 相机柜：选一台机身

用户从一个"相机柜"里挑选机身。每台机身的画幅、拍摄仪式和"不完美"都不一样，但出片口始终是刘海。

| 机身（原创外观） | 画幅 | 拍摄仪式 | 不完美效果 |
|---|---|---|---|
| **即显相机**（拍立得式） | 方形，带厚白边 | 一张一出，甩一甩加速显影，白边可写字 | 显影不均、边缘药水痕 |
| **大头贴机** | 四格竖条 | 拉帘、倒数、闪光、四连拍、限时装饰 | 闪光过曝、轻微错位 |
| **一次性相机** | 横幅 | 一卷 27 张，拍完前不能看。每拍一张都要在触控板上搓几下"过片"，咔哒咔哒；闪光灯要先按住充电 | 漏光、暗角、偏色 |
| **日期机** | 横幅 | 拍完自动在右下角印上橙色日期，可以手动把年份调成 1998 | 颗粒、日期戳的数码管字体 |
| **半格相机** | 一格拆成左右两张 | 连拍两张，自动拼成一对，常常凑出意外的组合 | 中间的分隔黑线 |
| **双反相机** | 正方形 | 取景器像一块磨砂玻璃，画面左右颠倒、四周发暗 | 暗角、柔焦 |
| **针孔相机** | 正方形 | 曝光 5 秒，期间不能动，一动就出现重影 | 真实的多帧叠加重影 |
| **摇摆 3D 相机** | 四格合成 GIF | 拍四张，每张之间提示你稍微挪一下头 | 左右来回晃动的立体感 |

**MVP 只做前两台**（即显相机、大头贴机），其余的放进路线图。

## 6. 大头贴机模式详细设计

| 现实里好玩的点 | Mac 上的做法 |
|---|---|
| 拉上帘子，进入一个小空间 | 按下快捷键，布帘从刘海落下盖住屏幕，其他窗口变暗，只剩取景框；刘海绿灯亮起，相当于"营业中" |
| 3、2、1 倒计时 + 闪光 | 倒数时整块屏幕瞬间变白当补光灯，屏幕真的会把脸照亮 |
| 四张连拍，来不及换姿势 | 每张之间只留两三秒，拍摄时不给预览 |
| 不能重拍 | 一次一条，没有"再来一张"按钮 |
| 站在出片口等纸条 | 相纸条伴着马达声从刘海吐出，一格一格显影 |
| 限时涂鸦、贴贴纸 | 出片后有 60 秒装饰时间，手写、贴贴纸，时间到自动定稿；用人脸识别把贴纸贴到头上；藏一个日系"大眼"滤镜当彩蛋 |
| 纸条可以撕开分给朋友 | 往中间一拖就撕成两半，一半留在桌面，一半生成分享图 |
| 每一条都不完美 | 随机漏光、颗粒、错位、色偏，再加日期戳 |
| 机器有个性 | 投币声、"请看镜头"提示音、快门声、出片马达声 |

**真机做不到、Mac 能做的：**

- **异地合拍**：两台 Mac 同时进入大头贴机，每一格里左边是你、右边是朋友，拍完两边刘海同时吐出同一条。
- **特别版相框**：节日自动换主题；也可以和使用数据挂钩，比如这周 commit 满 100 次，就解锁一款金色相框。

## 7. 胶卷系统

- 每台机身都可以换"胶卷"，不同胶卷对应不同的色调。
- 名字全部原创，例如"暖阳 400""夜航 800""旧报纸 黑白 100"，不使用真实胶片品牌。
- 一卷有固定张数（8、12、24 或 36 张）。拍完一卷会触发"送洗"：
  - 即显相机：立刻出片。
  - 一次性相机：第二天早上才"冲好"，用通知提醒你："你的照片冲洗好了。"
- 张数有限，每一张才会被认真对待；但不能限制日常截图（见第 11 节的待定问题）。

## 8. 声音和触感

声音大概占好玩程度的一半，每台机身都要有一套自己的声音：

| 时刻 | 声音 | 触感（压感触控板） |
|---|---|---|
| 进入相机 | 投币声，或机身开机的"嗡"一声 | 一次轻震 |
| 倒数 | 电子"哔"声，最后一声更高 | 无 |
| 快门 | 机械快门声，每台机身不同 | 一次重震 |
| 过片（一次性相机） | 齿轮咔哒声 | 每格一次轻震 |
| 出片 | 马达声 | 跟着出片节奏连续轻震 |
| 显影完成 | 很轻的"叮" | 无 |
| 撕开纸条 | 撕纸声 | 一次中震 |

## 9. 技术方案（macOS）

| 需要做的事 | 方案 |
|---|---|
| 找到刘海的位置 | `NSScreen.safeAreaInsets` 加上 `auxiliaryTopLeftArea` / `auxiliaryTopRightArea`，算出刘海的矩形（macOS 12 及以上） |
| 从刘海滑出照片 | 无边框的 `NSPanel`，窗口层级放在菜单栏之上，用 SwiftUI 做动画 |
| 发现用户截了图 | `NSMetadataQuery` 监听 `kMDItemIsScreenCapture = 1` 的文件 |
| 自己的"屏幕快门" | ScreenCaptureKit（需要"屏幕录制"权限） |
| 摄像头 | AVFoundation 的 `AVCaptureSession` |
| 人脸定位贴贴纸 | Vision 的 `VNDetectFaceLandmarksRequest` |
| 显影、漏光、颗粒、暗角 | Core Image：曝光和色温随时间变化，`CIRandomGenerator` 做颗粒，`CIVignette` 做暗角，再叠一层漏光贴图 |
| 甩一甩 | 只在用户拖着照片时检测鼠标方向的快速来回，不需要全局监听 |
| 手写笔画粗细 | 压感触控板的 `NSEvent.pressure` |
| 触感 | `NSHapticFeedbackManager` |
| 全局快捷键 | Carbon 的 `RegisterEventHotKey`，或开源库 KeyboardShortcuts |
| 针孔重影 | 5 秒内的摄像头帧取平均 |
| 白屏闪光 | 一个全屏白色窗口即可；调屏幕亮度需要私有接口，先不做 |

**存储和隐私：** 所有照片只存在本地，不上传。只有异地合拍需要联网，而且必须由用户主动发起。

## 10. 路线图

| 版本 | 内容 | 预计工作量 |
|---|---|---|
| **v0.1 MVP** | 即显相机：截图后从刘海出片，显影，甩一甩加速，吸在桌面，双击在 Finder 中打开；全套音效 | 一个周末 |
| **v0.2** | 大头贴机：拉帘、倒数、白屏闪光、四连拍、出片 | 一周 |
| **v0.3** | 白边手写、限时装饰和贴纸、撕成两半分享、软木板相册 | 一到两周 |
| **v1.0** | 相机柜（一次性相机、日期机、半格、双反、针孔），胶卷系统，没有刘海的 Mac 显示虚拟刘海 | 一个月左右 |
| **v2.0** | 异地合拍；iPhone 版，用灵动岛当出片口 | 待定 |

**推荐顺序：** 先做 v0.1 的网页原型，用模拟刘海验证"出片和显影"的节奏和手感，满意以后再写 SwiftUI。

## 11. 风险和待定问题

**风险**

- **品牌和商标**：Polaroid、Instax、Kodak、Lomography 等都是品牌名。产品里不能用它们的名字、logo 和标志性外观，机身和相纸都要原创设计。宣传时用"拍立得式""即显相机"这类通用说法。
- **和 Archie 撞车**：对方也在做"截图进刘海"。我们要守住"仪式感"的定位，不和它比效率功能。
- **机型**：只有部分 MacBook 有刘海。没有刘海的机型和外接显示器，要提供一个虚拟刘海。
- **权限**：摄像头、屏幕录制、截图文件夹访问（如果上架 App Store，在沙盒里要让用户手动授权一次）。
- **打扰**：显影和音效很可爱，但用户在工作中连续截十张图时会很烦。需要一个"安静模式"。

**待定问题**

1. 是所有截图都变成拍立得，还是只有按专门的快捷键才变？（倾向于后者，不打扰日常截图。）
2. 胶卷张数要不要真的限制？如果限制，用完以后怎么补充？
3. 怎么收费：一次买断，还是基础免费、更多机身和胶卷付费？
4. 名字：刘海冲印店、Notch Darkroom，还是出片口？
