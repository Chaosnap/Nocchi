# 决策记录

按时间倒序。每条写清楚：做了什么决定、为什么、对后续有什么影响。

## 2026-11-23

### D14 · 直接在 main 上开发；用 GitHub Actions 发行版本
- 仓库所有者决定：之后的改动直接推送到 `main`（`develop` 停用）。
- 推送 `vX.Y.Z` 标签触发 `release.yml`：测试 → 构建 → 打包 → 创建 GitHub Release。

### D13 · App 图标：手写矢量，macOS 圆角瓷砖规格，复古相机为主体
- 不突出刘海元素；主体是原创的复古旁轴式即显相机（香槟金属 + 黑色颗粒皮革 + 陶土橙快门帽），做旧毛边相纸从机顶升起、不出画框；胡桃木底与仓库所有者以往的图标风格一致。
- 源文件 `design/icon/nocchi-icon.svg`（由 `generate-icon.py` 生成）就是 macOS 图标；iOS 满版图标由 CI 从同一文件派生。

### D12 · 照片卡片盒用 3D 建模（SceneKit）
- 木质抽屉、立着的相片卡片、A–Z 分隔标签、桌上的照片堆都是真实 3D 物体：PBR 材质、柔和阴影、环境光遮蔽、相片表面有光泽涂层。
- 抽出 / 放回 / 叠放都是 3D 动画；首字母检索与「全部放回」是叠在场景上的 SwiftUI 控件。

### D11 · 相机用「分层建模」（2.5D），不用一张平面图
- 机身是一张高质量渲染图，镜头、快门键、闪光灯各自是独立的一层：镜头里是实时取景 + 玻璃镀膜反光（随手机倾斜移动），快门键能按下去，闪光灯会亮，整台相机随设备姿态有轻微视差和真实接触阴影。
- 原因：一张平面图一眼看上去廉价；分层后每个部件都有「实物感」，而且不需要真 3D 引擎。
- 部件位置记录在 `design/camera-instant-parts.json`（归一化坐标），换机身外观时重新测量即可。

### D10 · 配色：象牙白 + 炭黑 + 细铬 + 陶土橙
- 按仓库所有者给的参考图：象牙白机身、黑色多圈纹镜头、一道细铬圈、陶土橙快门键，不用粉色。
- 代码里统一用 `Palette`（macOS：`macOS/Nocchi/App/Palette.swift`）。
- 第二种可选外观是 80 年代方盒款（黑色机身 + 香槟银面板）。参考图是宝丽来 600 系列的标志性外观，所以做成同时代风格的原创机身：不带彩虹条和文字 logo，比例与细节不同。

### D9 · 参考「复古拍立得」网页玩法，取其精华
- 采用：默认题字「我可以见你吗？」+ 日期（可在设置里改，也可以每张单独改）；照片堆（新照片在最上层，旧照片被挤到一边）；相纸米黄底 + 暗角 + 柔边（新增 `edgeSoftness` 效果）；镜头与实时取景严丝合缝。
- 不采用：从音效网站扒音效（版权不清）——音效继续用程序合成。

### D8 · 美术素材全部原创，由 Codex 生成
- 参考图只用来对齐质感、材质、光影与配色；生成时明确要求原创造型、不出现任何品牌名 / logo / 文字 / 水印。
- `Ref_Image/` 是第三方图片（社交平台截图），不进公开仓库（`.gitignore`）。
- 生成提示词、来源与授权说明见 `docs/ASSETS.md`。

### D7 · 照片「出刘海」后飘进右上角的照片堆
- 出片 → 在刘海下方停一下（可以马上抓住甩）→ 没人拿就飘进屏幕右上角的照片堆。
- 被拖到别处的照片离开照片堆，停在用户放的位置（靠近屏幕边缘会像冰箱贴一样吸住）。

### D6 · 屏幕快门默认只响应专门的快捷键
- 回答构想文档「待定问题 1」：默认只有 ⌃⌥⌘S（或刘海面板上的「屏幕快门」）才冲印，日常截图不受打扰。
- 设置里可以开启「接管系统截图」，用 Spotlight 元数据监听 ⇧⌘3/4/5 的新截图。

### D5 · 胶卷张数只做「仪式感」计数
- 回答「待定问题 2」：每卷有张数，拍完自动换新卷并提示，不阻止拍摄。以后可加「严格模式」。

### D4 · 胶卷色调 = 参数配方运行时烘焙成 3D LUT
- 不打包第三方 LUT（许可证复杂）；15 卷内置胶卷都是原创参数（`FilmStocks.json`）。
- 支持导入用户自己的 `.cube`（校验大小、格点、数值），也能把任意胶卷导出成 `.cube`。

### D3 · 音效全部程序合成
- 快门、马达、叮、倒数、投币、撕纸等由 `SoundSynth` 实时合成，没有音频版权问题，安装包更小。

### D2 · 两个 App 分开实现，共享一个内核包
- `macOS/`（刘海出片口）与 `iOS/`（灵动岛出片口）是两个独立工程、各自的界面与交互。
- 与平台无关、可测试的逻辑放在 `Packages/NocchiKit`，两个 App 共用。

### D1 · GitHub Actions-Only CI + XcodeGen
- 本地不构建、不测试；工程文件由 `project.yml` 在 CI 中生成，不入库，避免 `.xcodeproj` 冲突。
- macOS 产物为 ad-hoc 签名 zip，iOS 产物为未签名 ipa。正式签名与公证需要在 GitHub Secrets 中配置证书后再加。
- 分支：最初是 `develop` → PR → `main`，现已改为直接在 `main` 开发（见 D14）。
